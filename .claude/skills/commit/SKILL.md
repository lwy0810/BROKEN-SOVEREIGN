# 커밋

1. `Docs/Rules/CommitRules.md`를 읽습니다.
2. `git status`와 `git diff`로 바뀐 내용을 확인합니다.
3. 현재 브랜치가 규칙 문서의 브랜치 규칙에 맞지 않으면 커밋하지 않고 알립니다.
4. 바뀐 내용이 두 가지 이상의 작업에 걸쳐 있으면 나눠서 커밋할 것을 제안합니다.
5. 규칙에 맞춘 커밋 메시지를 보여 주고, 승인을 받은 뒤 커밋합니다.
6. push는 따로 요청받았을 때만 합니다.

이 파일과 규칙 문서의 내용이 다르면 규칙 문서를 따릅니다.
